## C. P0 Fatal Blockers

### P0-1: Hardcoded Parallel API Key in Source Code and Git History
- **Location:** `backend/app/services/parallel_service.py:20`  
  ```python
  self.api_key = api_key or os.getenv("PARALLEL_API_KEY") or "REVOKED_PARALLEL_CREDENTIAL"
  ```
- **Git Commits:** `b81115b`, `4a2e5bd`
- **Impact:** Critical security breach. A judge or public viewer inspecting the GitHub repository can immediately extract the sponsor API token. Contradicts `SECURITY.md:31` ("No secrets or keys are stored in source code repositories").
- **Remediation:** 
  1. Remove the fallback string literal from `backend/app/services/parallel_service.py`. Enforce strict `os.getenv("PARALLEL_API_KEY")` with an explicit error or local test skip.
  2. Rewrite git history or use environment variables in test harnesses.
  3. Ensure `.env` is gitignored (it currently is, but the default argument leaked it into code).

### P0-2: Production Deployment Claim vs. Reality (Cloud Run Absent)
- **Location:** `DEPLOYMENT.md`, `DEVPOST.md:5`, `frontend/app/page.tsx:132`
- **Observed Evidence:**
  - `gcloud run services list --platform managed --region us-central1` returned no `obstat` services.
  - `frontend/app/page.tsx:132` hardcodes: `const API_BASE = 'http://localhost:8000';`
- **Impact:** DEVPOST claims "Google Stack: ... Cloud Run", and `DEPLOYMENT.md` presents deployment commands as if live. If judges click a Devpost submission URL that requires `localhost:8000`, the application will fail to fetch backend data.
- **Remediation:**
  1. Deploy `obstat-backend` and `obstat-frontend` to Cloud Run, or configure a working cloud host.
  2. Change `API_BASE` in frontend to support `process.env.NEXT_PUBLIC_API_BASE || 'http://localhost:8000'`.

## D. P1 Winner Blockers

### P1-1: Benchmark Claiming "100.0% Accuracy" Overclaims Real-World Search
- **Location:** `README.md:47-53`, `DEVPOST.md:43-52`, `backend/tests/run_proof_benchmarks.py`
- **Analysis:** `run_proof_benchmarks.py` generates synthetic string cases (`case_ev_001` to `case_ev_100`) and asserts that if `cat_name == "CLEAN_FICTIONAL"`, `expected_outcome == "NO_MATCH_FOUND_IN_SCOPE"` and sets `is_valid = True`. It does not execute live web searches or pass noisy web text into an independent classifier.
- **Judge Perception:** Judges who inspect `schemas/evidence_benchmark_results.json` will immediately see synthetic generated strings (`"FICTIONAL_CHAR_001 VANE"`, `"BRAND_ENTITY_031 INC"`) and recognize that the 100% figure measures internal unit logic, not empirical precision against the live web.
- **Remediation:** Frame the metric honestly: *"100.0% Adjudication Policy Compliance & Fail-Closed Invariant Enforcement across 100 Controlled Synthetic Test Cases"* rather than general "100% Accuracy".

### P1-2: Playwright Live Integration Test Bypasses File Upload
- **Location:** `frontend/tests/live-integration.spec.ts:25-37`
- **Analysis:** The live E2E test creates a project via wizard, which starts with zero claims, but then checks for chips (`MERCER VALE RECORDS`) that only exist in pre-seeded projects. It does not upload a `.txt` screenplay file through the UI in automated testing.
- **Remediation:** Add a true end-to-end test step in Playwright that attaches `Starlight_Heist_Draft_12.txt` via `setInputFiles`, triggers the backend upload endpoint, and asserts the rendered Courier Prime screenplay pane.

### P1-3: Fallback Rule Parser in Extractor Suppresses Live Gemini Errors
- **Location:** `backend/app/adk/extractor.py:93-100`
- **Analysis:** If Vertex AI Gemini fails (e.g., credential expiration or network timeout), `GeminiExtractor` catches all exceptions and silently falls back to `_fallback_rule_extraction` (a basic regex matcher for scene headers and character cues).
- **Risk:** A judge testing without proper Google Cloud credentials might observe the app functioning and mistakenly believe regex is posing as Gemini AI.
- **Remediation:** Add explicit UI or API metadata (`extractor_mode: "VERTEX_AI_GEMINI_2_5_FLASH"` vs `"STRUCTURAL_FALLBACK"`) so judges know exactly when Gemini is live.

### P1-4: Upstream Contribution Layer is Tier C (Local Documentation Only)
- **Location:** `CONTRIBUTIONS.md`
- **Analysis:** The document details an excellent architectural pattern ("Google ADK 2.x Egress Firewall Integration Pattern"), but it is purely local documentation. It has not been submitted as an issue, PR, or discussion to the Google ADK or Parallel repositories.
- **Remediation:** Title this section "Architectural Blueprint & Reusable Reference Integration" rather than claiming completed external contributions.

## J. Benchmark Validity & Ablation Analysis

### 1. Evidence Benchmark (`schemas/evidence_benchmark_results.json`)
- **Number of Cases:** 100
- **Reported Result:** 100.0% Passed
- **Auditor Finding:** **Self-Referential Test Harness.**
  - In `backend/tests/run_proof_benchmarks.py`, `CLEAN_FICTIONAL` cases are hardcoded strings (`FICTIONAL_CHAR_001 VANE`). The test sets `usable_evidence = 0` and `is_valid = True` without making web requests.
  - **Verdict:** Valid as a unit test verifying that zero evidence yields `NO_MATCH_FOUND_IN_SCOPE`. **Invalid as a public claim of 100% empirical web search accuracy.**

### 2. Revision Invalidation Benchmark (`schemas/revision_benchmark_results.json`)
- **Number of Cases:** 100
- **Reported Result:** 100.0% Invalidation Accuracy, 55.0% Search Reduction
- **Auditor Finding:** **Valid State Machine Evaluation.**
  - The 100 mutations (30 Retained, 25 Moved, 20 Renamed, 10 Modified, 10 Removed, 5 Added) accurately test `RevisionInvalidationEngine.compute_revision_diff`.
  - The 55% search reduction reflects that 30 Retained + 25 Moved items safely preserved evidence without re-querying.

### 3. Load-Bearing Mechanism Ablation
- **Ablation A: Remove Egress Firewall:** Outbound queries would leak dialogue context (e.g. `test_03_egress_leak_dialogue_attempt` fails immediately with plot leaks).
- **Ablation B: Remove Verbatim Span Matching:** Hallucinated web snippets would clear entities falsely, causing catastrophic legal risk.
- **Ablation C: Remove Revision Diff:** Every script revision would force 100% re-research, multiplying API costs and introducing race conditions.
